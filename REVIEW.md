# REVIEW.md: Starter Code Defect Audit & Resolution

This document lists all defects identified in the starter implementation of `app/main.py`, their impact on correctness, concurrency, and performance, and the corresponding fixes implemented.

| # | Location | Defect | Impact | Fix |
|---|---|---|---|---|
| **1** | Startup / Client init (`main.py:22-24`) | No indexes created on database startup. | Concurrent requests produce duplicate records; queries on 100k+ records result in full collection scans (`COLLSCAN`), causing severe latency. | Implemented a FastAPI `lifespan` handler creating unique index on `employees.emp_code`, compound unique index on `attendance_logs(emp_code, date)`, and compound query indexes. |
| **2** | `health` (`main.py:72-74`) | Returns static `{"status": "ok"}` without testing database connectivity. | Endpoint returns HTTP 200 even when MongoDB is offline, violating readiness probe contract (Rule requirement: 503 on DB failure). | Added `client.admin.command("ping")` within `try/except` and raised HTTP 503 (`SERVICE_UNAVAILABLE`) on connectivity failure. |
| **3** | `compute_late_minutes` (`main.py:33-37`) | Flawed grace period logic (`minutes if minutes > 10 else 0`). Integer division truncates seconds before comparing. | Punch-in at `09:40:01` (shift `09:30`) has 601 elapsed seconds; truncated to 10 minutes, `10 > 10` evaluates to False, returning 0 instead of 10 (violates Rule R2). | Measured total elapsed seconds from `shift_start`: if `diff_seconds > 600`, return `int(diff_seconds // 60)`, else 0. |
| **4** | `compute_late_minutes` (`main.py:33-37`) | Modifies timestamp directly (`replace(hour=h, minute=m)`) without timezone anchoring or overnight shift handling. | Replaces UTC hour with IST shift time, corrupting instant calculations; overnight shifts punching in past midnight compute shift start on the wrong calendar day. | Anchored `shift_start` to the attendance date in IST (`UTC+05:30`) and computed the difference between timezone-aware IST datetimes. |
| **5** | `compute_work_hours` (`main.py:40-42`) | Uses Python built-in `round()`. | Python `round()` uses banker's rounding (round half-to-even) instead of round half-up, failing Rule R4. | Used `decimal.Decimal` with `ROUND_HALF_UP` on total seconds divided by 3600. |
| **6** | `compute_overtime` (`main.py:44-48`) | Missing 30-minute threshold check mandated by Rule R3. | Punching out 15 minutes after shift end awards 15 minutes of overtime instead of 0. | Added threshold check: only return `int(diff_seconds // 60)` when `diff_seconds >= 1800` (30 minutes), otherwise return 0. |
| **7** | `compute_overtime` (`main.py:44-48`) | Overnight shifts (`shift_end <= shift_start`) do not increment calendar day for shift end. | Shift end is anchored to the shift start date instead of the next calendar day, producing massive negative or corrupted overtime numbers. | Detected overnight shifts and set shift end calendar day to `attendance_date + timedelta(days=1)`. |
| **8** | `compute_overtime` (`main.py:44-48`) | Subtracts naive datetime from timezone-aware datetime (`tzinfo=IST`). | Throws runtime crash `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Ensured both datetimes are converted to timezone-aware IST datetimes before subtraction. |
| **9** | `create_employee` (`main.py:77-86`) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent requests with the same `emp_code` both pass the `find_one` check, creating duplicate records or crashing unpredictably. | Enforced database unique index on `emp_code` and caught `pymongo.errors.DuplicateKeyError` to return HTTP 409. |
| **10** | `create_employee` (`main.py:81-85`) | Stores `created_at` as local naive datetime and serializes it as an ISO string. | Fails OpenAPI contract and MongoDB specification: instants must be UTC BSON datetimes in DB and integer epoch milliseconds in API responses. | Stored UTC datetime in MongoDB and converted `created_at` to integer epoch milliseconds in response. |
| **11** | `EmployeeIn` model (`main.py:53-60`) | Lacks input validation for `shift_start != shift_end`, email, `EMP` code regex, and date formats. | Accepts invalid payloads and identical shift start/end times with 201 instead of returning HTTP 422. | Added Pydantic field regexes (`EMP\d{4,6}`, email, `HH:MM`, `YYYY-MM-DD`) and model validator rejecting `shift_start == shift_end`. |
| **12** | `list_employees` (`main.py:93`) | Off-by-one pagination skip: `skip = page * page_size`. | For `page=1, page_size=20`, `skip` evaluates to 20, completely skipping the first 20 records. | Changed skip calculation to `skip = (page - 1) * page_size`. |
| **13** | `list_employees` (`main.py:94`) | `total` counts entire collection (`count_documents({})`) regardless of filters. | Total ignores `department` filter, returning whole-company count rather than filtered count (Rule R10). | Changed to `total = db.employees.count_documents(q)`. |
| **14** | `list_employees` (`main.py:95`) | Missing deterministic sort order. | Records returned in arbitrary physical MongoDB storage order rather than contract specification (`emp_code` ascending). | Added `.sort("emp_code", 1)` to the cursor. |
| **15** | `punch_in` (`main.py:101`) | Does not check if employee exists; crashes on `None["shift_start"]`. | Request with unknown `emp_code` crashes with HTTP 500 `TypeError` instead of returning HTTP 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| **16** | `punch_in` (`main.py:104`) | Check-then-insert race condition (`find_one` then `insert_one`). | Two simultaneous punch-in requests for the same date both pass the check and attempt inserts. | Enforced compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| **17** | `punch_in` (`main.py:103`) | Date determined using local clock (`ts.date().isoformat()`) without Rule R1 overnight shift rule. | Punching in at 01:00 AM on an overnight shift assigns today's calendar date rather than the previous day's shift date. | Implemented `get_attendance_date()`: for overnight shifts, if punch-in IST time is earlier than `shift_end`, date belongs to previous day. |
| **18** | `punch_in` & `list_attendance` (`main.py:119, 149`) | Injects `"id": str(res.inserted_id)` into response document. | Leaks internal database ObjectId; OpenAPI contract explicitly forbids `id`/`_id` on attendance records. | Removed `doc["id"]` assignment; records are addressed exclusively by natural key `(emp_code, date)`. |
| **19** | `list_attendance` (`main.py:144-147`) | In-memory sorting and pagination (`list(db.attendance_logs.find(q))`). | Loads entire 100k+ document collection into Python heap memory, causing memory exhaustion and massive latency. | Replaced with database-side `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` and `count_documents(q)`. |
| **20** | `list_attendance` (`main.py:125-132`) | Missing validation for `date_from > date_to` and status values. | Supplying inverted date range or unrecognized status returns 200 with empty items instead of HTTP 422. | Added validation raising HTTP 422 for `date_from > date_to` and invalid status enums. |
| **21** | Instants (Across helpers & endpoints) | Instant sub-second microseconds are not truncated. | Fails Rule R1: instants must be truncated to whole seconds before calculation, and truncated value stored and returned. | Added microsecond truncation (`.replace(microsecond=0)`) on all incoming and computed instants. |
| **22** | `list_attendance` & `regularize_attendance` (`main.py`) | Path/query date parameters accepted malformed non-date strings without schema validation. | Malformed date strings (e.g., `2026-02-31` or `abc`) bypassed regex, corrupting queries or raising unhandled exceptions instead of 422. | Added explicit `dt_date.fromisoformat()` validation to reject invalid date strings with HTTP 422. |
| **23** | `late_leaderboard` (`main.py`) | Leaderboard ranking initially used `$rank` (standard competition ranking skipping ranks on ties). | The leaderboard requirement specifically mandates dense rank semantics (`$denseRank`: 1, 2, 2, 3) where consecutive ranks are not skipped on ties. | Replaced `$rank` with `$denseRank` in `$setWindowFields` with secondary sort on `_id` (`emp_code` ascending) for deterministic display ordering. |
| **24** | Serialization helper `dt_to_epoch_ms` (`main.py:65`) | Assumed input is exclusively a `datetime` object, accessing `.tzinfo`. | If an already-serialized numeric timestamp (e.g. from seed or nested history) was passed, threw `AttributeError: 'int' object has no attribute 'tzinfo'`. | Added type check `if isinstance(dt, (int, float)): return int(dt)` before checking `.tzinfo`. |

---

## Items Examined and Confirmed NOT to be Defects

1. **Absence of MongoDB ObjectId references between collections**: `emp_code` is the customer-assigned natural business key. Addressing attendance records by `(emp_code, date)` and employees by `emp_code` without ObjectId references is intentional by design.
2. **Absence of endpoints creating `ABSENT` / `LEAVE`**: Rule R6 and OpenAPI state that punch endpoints only create presence records (`PRESENT`, `WFH`, `ON_DUTY`). `ABSENT` and `LEAVE` records originate from back-office seed data or manual regularization (`PATCH`).
